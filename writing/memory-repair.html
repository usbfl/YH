示例文章 · MEMORY SYSTEMS

纠正记忆之后，
旧结论怎么办？

在记忆修改后，把已经依赖旧信息做出的推论同步修复，为什么比“修改一条事实”更难？

本文为基于 TracePatch v0.2 仓库和简历制作的示例文章；不代表已发表的研究成果。

1. 问题不止发生在长期知识库

假设知识库中某项规则被纠正，系统已经基于旧规则生成的报告、摘要与行动计划并不会天然同步更新。类似情况还会出现在一次任务内部：工具的新结果否定了之前的中间结论，却未触发已完成步骤的复核。

2. 怎么找到受影响的内容？

最可靠的是显式记录“结论 A 依赖证据 B”。但在真实系统中依赖链可能缺失，因此 TracePatch 同时考虑文本相似度、实体匹配与图关系，把可能受影响的内容召回为待检查候选。

事实被更正→候选关联定位→有限预算排序→复核 / 修复

3. 为什么要进行风险排序？

如果只有有限的核验次数，遍历全部历史结论不现实。系统需要考虑可能错误的程度、结论未来被再次使用的机会、当前任务是否依赖它，以及重新核验的成本，优先处理影响大的候选。

4. “找到相关”不等于“应该修改”

文本匹配只能说明两个内容相关，不能证明后一项的结论一定错误。真正修改前应重新查看原始证据，必要时将缺少证据的结论标记为待确认，避免一次纠错引发新的误修复。

5. 当前系统能验证什么？

TracePatch v0.2 使用离线实验对比方法、预算和缺边条件，并建立“摘要—写入—再检索—下一任务”的闭环；短期任务由确定性执行器承担。它尚不能证明真实大模型在开放式任务中具有同等的续做效果。
